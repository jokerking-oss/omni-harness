## 1 背景和结论

Exoharness 与我们解决相似问题，但核心采用 Rust，本项目采用 Python、LangGraph 和 Next.js。最值得引入的是它对能力发现、精确选择和上下文证据的处理方式。直接移植整个运行时会重复现有功能并增加双栈维护成本。

第一阶段解决已在源码确认的缺口：工具批量选择存在部分成功却没有缺失提示的情况。新增显式精确名称列表，要求整批解析成功后才加载；允许按真实 MCP 服务身份限定查找，避免通过工具名前缀猜测来源。保留原查询语法以兼容既有调用。

本 PRD 保留第一阶段决策，并在第 9 节确定用户要求继续完成的五项后续需求；最终验收见第 10 节。不把其他项目的产品介绍当作我们尚未具备的能力，也不承诺未经测试的 Token 节省比例。

## 3 用户和场景

- 技能作者声明一组协作工具时，需要知道是否全部可用，不能无声地少加载一个。
- Agent 连接多个 MCP 服务时，需要将同名或相近用途的工具限定到指定服务。
- 运维人员需要通过既有工具结果和 promotion 审计确认实际加载内容。

示例：技能需要 `catalog_lookup` 和 `order_submit`，但第二个名字已过期。现状可能只加载前者；新增严格请求应说明未解析的名字，整批不新增工具，让 Agent 修正请求后重试。

## 4 第一阶段范围

### 4.1 对外契约

扩展现有 `tool_search`，不增加平行执行系统、HTTP 路由或数据库表：

```json
{"names": ["catalog_lookup", "order_submit"], "server_name": "commerce"}
```

- `query` 改为可省略，默认空字符串；旧 `query`、`select:`、`+required` 和正则查询保持原行为。
- `names` 为可选、非空精确名称数组，最多 32 个，每个名称最多 256 字符。它与非空 `query` 互斥；两者同时提供时返回可理解的错误，不加载子集。
- 名称仅去除首尾空白、按请求顺序去重；不忽略大小写、不猜原生名或别名、不做模糊替换。
- 整个批次的每个名称必须在当前构建的候选目录和可选服务范围内命中，且在整个目录中名称唯一。任何不存在、来源不匹配、名称歧义或空白名称均使整批失败。执行与 promotion 仍仅按工具名定位，服务限定不能消除全局重名；重名需调整服务配置提供唯一名称。
- 严格批量请求不受关键词搜索前五项限制；成功时返回全部 schema，并沿用当前 catalog hash 的 promotion 合并机制。
- `server_name` 使用 MCP 的无凭据来源元数据精确比较。缺少来源的遗留工具仍能参与未限定查询，但不能冒充指定服务。未知服务不回退到全目录。
- 服务限定也适用于旧 `query` 查询。服务限定本身不授权任何工具，不加载整个服务，不调用业务工具。

### 4.2 权限和失败语义

- 延续构建期授权过滤、运行期技能策略和执行前授权；搜索不得扩大权限。
- 活跃技能拒绝严格批次中的任意名称时，整批不新增 promotion，结果不包含被拒绝工具的 schema。
- 技能禁止名称必须在执行 `tool_search` 内层函数前拒绝，避免原始 schema 被 `on_tool_end` 提前写入 journal；最终结果过滤仍保留作为防御。
- 失败返回 `ToolMessage.status=error` 和修正指导。不能把错误写成成功的部分结果。
- 相同 catalog hash 下，空 promotion 保留已有加载集合；目录变化仍遵循原有 hash 失效规则。
- catalog hash 纳入无凭据的 MCP 来源身份与构建内名称碰撞标记；服务身份改变或碰撞状态变化会让旧 promotion 失效。组装阶段去重保留碰撞证据，不修改共享工具实例。
- 继续使用现有调用与 promotion 审计；只有实际成功的加载才计入有效 promotion。
- 不引入自动修复或自动重试，也不将模型提供的名字当成授权凭据。

### 4.3 非目标

第一阶段不实现服务摘要列表、分页游标、自动纠错别名、历史 schema 投影压缩、跨会话交付库、语音服务或新权限模型。服务摘要必须在授权过滤后计算数量并分页，不能先展示全目录再删除被禁止项目。

## 5 验收标准

| 编号 | 条件 | 预期 |
| --- | --- | --- |
| A1 | 精确指定超过五个有效工具 | 全部返回并加载，顺序确定，重复输入只加载一次 |
| A2 | 批次包含有效与不存在名字 | 报告未解析名字，无部分 schema，无新增 promotion |
| A3 | 已有 promotion 后严格请求失败 | 同目录已有集合保留 |
| A4 | 工具名字重复导致身份歧义 | 即使指定服务也拒绝；配置唯一执行名后再加载 |
| A5 | 指定错误或未知服务 | 空结果或严格错误，不从其他服务补齐 |
| A6 | 批次包含技能策略禁止的工具 | 同步、异步链路均整批拒绝；没有被禁止 schema 或有效 promotion 审计 |
| A7 | 全部允许的严格批次 | 下一模型轮绑定所有请求的工具；未请求工具继续隐藏 |
| A8 | 旧查询和旧权限路径 | 原有测试保持通过，不改变旧 `select:` 的部分匹配兼容性 |
| A9 | 空数组、超大数组、过长名称、空白名称、同时提供 query/names | schema 校验或明确错误，不加载工具 |
| A10 | 来源元数据含其他配置 | 搜索只读取逻辑服务身份，不输出凭据和连接配置 |
| A11 | 同名同 schema 工具来源从 A 改为 B | catalog hash 改变，A 的持久 promotion 不应用于 B |
| A12 | 权限拒绝的严格批次带运行日志回调 | 内层工具不执行，回调和 journal 不接收被拒绝 schema |

## 6 实施和验证

1. 先提交可失败的目录、工具调用和权限回归测试。
2. 扩展目录精确解析与服务限定，在当前工具闭包内生成 schema 和 promotion。
3. 更新技能策略结果过滤，使严格批量请求保持原子性；同步和异步复用同一规则。
4. 使用真实 LangGraph 图和假模型验证下一轮工具绑定、失败保留及审计，测试不调用外部模型或 MCP。
5. 更新 README 和相关 AGENTS.md，记录参数、兼容性和授权语义。
6. 运行相关离线回归、完整离线套件及 blocking-I/O 检查；区分改动回归与 Windows/环境已有失败。

发布使用原有 `tool_search.enabled` 开关，不新增迁移。回滚可恢复原工具定义和过滤器；新增参数不会写入新的持久化结构。

## 7 分期策略

P1 的服务摘要发现和历史 schema 投影按独立模块实现。摘要发现需满足：授权后分页、绑定查询与 catalog hash 的游标、缺失来源兼容、切换技能后不沿用旧权限缓存。投影需保留完整 journal、完整工具调用配对及重新加载能力；真实收益评估使用同模型、同任务和相同验收标准，比较请求字节与实际用量。

P2 围绕跨会话寻找正式交付、定位资料块及检查模型请求变化，扩展现有项目资料架、交付凭据和日志界面。具体边界见第 9 节。

## 9 后续阶段的确定需求

用户在第一阶段交付后明确要求按照 PRD 完成开发。以下需求进入实施，不再仅作为候选；分别实现和验收，复用现有权限、运行日志、项目资料与交付凭据。

### 9.1 分层能力发现

`tool_search` 新增只读 `mode=services|tools`，默认 `mode=load` 保持兼容。服务页返回服务身份与允许工具数量；工具页返回名称、简短说明和来源，不返回参数 schema，不产生 promotion，不执行业务工具。无来源的遗留工具保留独立归属。按稳定次序分页，每页最多 20 项；游标绑定目录版本、查询、范围、页大小和当前权限。查询或技能策略切换后旧游标失效，提示从第一页重查。

技能过滤必须在统计数量和分页之前执行，不能暴露被禁止工具的名称、摘要或数量；运行日志与模型接收到相同的安全结果。Agent 可先查服务，再查该服务工具摘要，最后用严格 names 加载。

### 9.2 历史目录结果投影

只在模型请求副本中，把已经成功加载且当前仍绑定的历史 schema 转为简短加载凭据，保留完整原始消息、journal 和检查点。按服务器来源标记、目录版本、成功状态及实际 schema 名称确认资格，不通过工具名字猜测可压缩业务结果。调用和结果配对不删除，失败、未知来源和目录变更后的消息保持原样。当前未绑定的 schema 不得声称仍可用；可再次显式加载。

验收采用确定性离线场景比较投影前后的请求字节和消息配对，并保留同任务、同模型、成功交付与实际用量的真实基准入口；未经真实运行不报告 Token 节省比例。

### 9.3 模型请求证据

复用 RunJournal 和现有运行事件 API，记录每次模型请求的边界、部件类别、数量、字节、SHA-256、工具 schema 名称/摘要哈希以及与前次请求的变化。能够接入最终 provider payload 的适配器标记为 provider payload；其他适配器明确标记模型输入边界，不能伪称最终网络请求。

证据不保存原始提示、用户内容、文件内容、凭据、请求头或完整网络 payload。每轮 Debug 明细可查看证据并支持 loading/error/空状态与旧运行兼容；不增设平行 trace 数据库。

### 9.4 项目资料结构读取和字面搜索

在已有项目资料工具上新增结构块目录、单块读取和字面搜索。支持 Markdown 标题、段落、代码及表格；表格分页重复表头，返回字符/行定位。调用者可固定文档 SHA-256 及服务文本版本，版本不匹配时拒绝混读。

所有操作沿用当前项目、owner-scoped 文档仓库和受限文件路径，限制扫描字节、返回命中和单块大小。无 OCR、向量检索或新资料数据库；非结构化输入降级为文本段落。Agent 工具必须在正常项目会话中实际可用。

### 9.5 跨会话交付聚合

新增工作区交付入口，列出当前用户可访问会话的近期正式交付，展示文件、来源会话/执行、时间和执行状态，支持打开现有预览、下载和回原会话。仅从持久化的正式 `run.delivery` 凭据提取文件，忽略模型文本及文件夹扫描。

SQL 事件存储可采用授权后的游标分页；默认 memory/jsonl 配置至少支持有明确范围说明的近期执行视图。读取范围、每页和文件数量有硬上限；不把历史凭据当作文件内容快照，界面说明打开的是当前文件版本。会话或权限失效后不可继续访问文件。必须具备空状态、重试、加载更多和过期请求取消。

### 9.6 交付门禁

每阶段均先写可失败测试，再实现；运行相关后端离线测试、前端单元测试、类型和 lint 检查，针对新增页面完成浏览器验收或记录无法运行的具体限制。已有环境失败单列，不能跳过或提高预算伪造通过。最终交付记录逐项标明上述五项需求的实现文件、测试及剩余限制。

第 4 节及第 9 节的开发范围已完成，相关离线回归通过，新增交付页可通过工作区导航进入。实现细节、复现命令和检查结果见 [完整交付验证记录](../pr-evidence/2026-10-11-exoharness-complete.md)。
